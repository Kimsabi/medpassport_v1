# 약 여권 (Medication Passport) — 시연용 웹 프로토타입

혼자 사는 어르신도 자주 먹는 약 정보를 **QR 하나로 어디서든** 보여줄 수 있게 하는 서비스의 시연용 웹입니다.
서버 없이 HTML/JS만으로 동작하며, GitHub Pages에 그대로 올리면 휴대폰과 노트북에서 바로 시연할 수 있습니다.

> 모든 인물·기관·처방은 **가상 데이터**입니다. 데이터는 각 브라우저의 localStorage에만 저장됩니다.

---

## 1. 구성

| 화면 | 파일 | 기기 | 내용 |
|---|---|---|---|
| 시작 화면 | `index.html` | 노트북 | 역할 선택, 휴대폰으로 여는 QR, 시연 순서, 데이터 초기화 |
| 어르신·보호자 앱 | `app.html?as=elder` / `app.html?as=guardian` | 휴대폰 | 쉬운/기본 모드, QR 보여주기, 처방 등록(QR·OCR), 약 상세, 보호자 공유 설정, 열람 기록 |
| 업무용 웹 | `work.html#pharmacy` / `#clinic` / `#audit` | 노트북 | 약국 처방 등록·QR 발급·취소, 진료 QR 스캔, 보안 감사 |
| 나란히 보기 | `split.html` | 노트북 1대 | 왼쪽 휴대폰 + 오른쪽 업무용 웹 (실시간 연동) |

```
├── index.html  app.html  work.html  split.html
├── assets/
│   ├── style.css      공통 디자인 (와이어프레임 톤)
│   ├── core.js        약품 마스터 · 가상 데이터 · 암호화 · QR · 스캐너
│   ├── app.js / app.css     어르신·보호자 앱
│   └── work.js / work.css   약국 · 진료 · 감사
└── vendor/            qrcode-generator, jsQR, Pretendard 폰트 (인터넷 없이 동작)
```

## 2. GitHub Pages에 올리기 (5분)

1. GitHub에서 새 저장소를 만듭니다 (예: `yak-passport`). **Public**으로 만들어야 무료 Pages를 쓸 수 있어요.
2. zip을 풀면 나오는 `yak-passport` 폴더 **안의 파일 전체**를 업로드합니다 (`index.html`이 저장소 맨 위에 오도록).
   - 웹에서: 저장소 → **Add file → Upload files** → 파일·폴더 끌어놓기 → **Commit changes**
3. 저장소 **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main / (root)** → **Save**
4. 1~2분 뒤 `https://<아이디>.github.io/yak-passport/` 주소가 생깁니다.

> **꼭 https 주소로 여세요.** 카메라와 QR 암호화(Web Crypto)는 https나 localhost에서만 동작합니다.
> 파일을 더블클릭해서 여는 방식(`file://`)은 카메라가 안 될 수 있어요.

**내 컴퓨터에서 테스트하기:** 폴더에서 `python -m http.server 8000` → 브라우저에서 `http://localhost:8000`

## 3. 시연 준비물과 방식

**추천: 노트북 1대 + 휴대폰 2대 (+ USB QR 리더기)**
- 노트북: `work.html` (약국 → 진료 → 감사 탭)
- 어르신 폰: 시작 화면의 "어르신 앱" QR을 찍어서 열기
- 보호자 폰: 시작 화면의 "보호자 앱" QR을 찍어서 열기
- QR 리더기: 노트북에 꽂고 진료 탭을 열면 바로 인식합니다 (키보드처럼 입력되는 방식)

**노트북 1대만 있을 때:** `split.html`을 엽니다. 진료 탭의 **"환자 화면의 QR 읽기"** 버튼이 리더기 역할을 대신합니다.
왼쪽 휴대폰 화면에서 바꾼 내용(복약 체크, 공개 범위, 연결 해지)이 오른쪽에 바로 반영되고, 반대로 의료진이 열람하면 왼쪽 휴대폰에 알림이 뜹니다.

### QR 리더기 구매·사용 팁
- **"2D", "휴대폰 화면 인식"** 이 적힌 USB 바코드 스캐너를 고르세요 (1D 전용은 QR을 못 읽어요).
- 노트북이 **한글 입력 상태**여도 자동으로 영문으로 복구해서 읽지만, 시연 전에 **한/영 키로 영문**에 두는 게 가장 안전합니다.
- 진료 탭 상단의 `● QR 리더기 대기`가 초록색이면 입력을 받을 준비가 된 상태입니다. 회색이면 화면 빈 곳을 한 번 클릭하세요.
- 리더기·카메라가 말썽이면 진료 탭 아래 **"시연용 샘플"** 버튼으로 같은 장면을 보여줄 수 있습니다.

## 4. 시연 시나리오 (약 5~7분)

| # | 장면 | 화면 | 보여줄 포인트 |
|---|---|---|---|
| 1 | 약국에서 등록 | 노트북 · 약국 | 본인 확인 → 처방 입력(DUR 경고) → 어르신과 **보호자 공유 범위** 결정 (① 복약 현황 포함 약, ② 약 상세 공유 약) → 보호자 연결(선택, 가족/보건소 담당자, **보호자 휴대폰 번호**) → **안내지 인쇄** 또는 **화면에 띄우기** |
| 2 | 어르신 앱에 등록 | 어르신 폰 | 첫 실행 **크게 보기** → '약 등록' → ① 처방 등록 QR 찍기 → 등록 완료(음성 안내). 같은 QR을 다시 찍으면 "이미 등록한 처방"(1회용) |
| 3 | 보호자 연결 | 보호자 폰 | '가족' → ② 보호자 연결 QR 찍기 → '어머니' 약 여권 추가, 어르신 폰에 "보호자로 연결됐어요" 알림. **다른 번호의 휴대폰으로 찍으면 거부** (약국에서 번호를 바꿔 발급하면 시연 가능) |
| 4 | 보호자 화면 | 보호자 폰 | ① "아직 드실 약이 남았어요"처럼 **합계만**, ② 상세 공유한 약만 표시. 수면제 등 숨긴 약은 이름·개수·시간 모두 안 보임. 어르신이 공유를 켜면 바로 반영(나란히 보기) |
| 5 | 병원 접수 | 어르신 폰 → 노트북 · 진료 | '의료진에게 보여주기' → 리더기에 대기 → 알레르기 배너, DUR(조영제-메트포르민), INN·ATC 약 목록, 일본어/영어 표시 전환 |
| 6 | 보안 | 노트북 · 진료 | 같은 QR 다시 찍기 → **"이미 사용된 코드"**, 샘플 "5분 지난 QR" → **"만료된 코드"**, "위조된 코드" → **복호화 실패** |
| 7 | 응급 · 감사 | 노트북 · 진료/감사 | 앱의 응급 QR → 인터넷 없이 환자가 고른 최소 정보만, **기준일** 표시. 감사 화면에는 허용·거부 기록만 쌓이고 **의료 정보는 안 보임** |
| 8 | 환자 통제권 | 어르신 폰 | 알림·열람 기록 확인, 공유 끄기, 보호자 **연결 해지** → 보호자 폰에서 즉시 차단 |

## 5. 반영 내역 (PPT용)

### 5-1. 현지 피드백 반영

| 피드백 | 반영 |
|---|---|
| 츠쿠바대: 보호자 없는 독거 고령자 | **약국 등록 지원** (약사가 본인 확인·처방 등록·공유 범위 설정을 함께) · 보호자 대신 **보건소 돌봄 담당자** 연결 |
| 츠쿠바대: 접근성 | **쉬운 모드** (큰 글씨, 핵심 버튼 2개, 시간대별 복약 체크) · **음성 안내** |
| 메이지대: 앱 사용 어려움 | 약국 대면 안내 + 큰 글씨 안내지 · 접수대 QR 리더기에 "갖다 대기" (카카오페이·QR 체크인과 같은 동작) |
| 타나카 교수: 보호자에게 숨기고 싶은 약 | **공유 2단계**: ① 복약 현황(고른 약의 합계만, 하루 단위 기본) ② 약 상세(허용한 약만). 기본값은 최소 공유 · 숨긴 약은 개수·시간으로도 추측 불가 · 보호자 조회 시 **환자 알림** · **즉시 해지** |
| 타나카 교수: 응급 QR 포함 정보 선택 | 앱의 응급 QR에 알레르기 / 보호자 연락처 / 복용 약 포함 여부를 환자가 선택 |

### 5-2. 개발 과정에서 발견한 추가 개선 (자체 개선)

- **처방전 촬영 입력 (OCR 확인)**: 처방전을 손으로 입력하는 번거로움 → 사진 촬영 후 자동 인식, 신뢰도가 낮은 항목만 직접 확인
- **"복약 여부만 공개"의 추측 위험**: 약별로 복약 여부만 보여줘도 시간대·개수로 숨긴 약을 짐작할 수 있음 → 합계 방식(① 복약 현황)과 상세(② 약 상세)로 분리
- **보호자 연결 QR 오용 위험**: 1회용만으로는 "먼저 찍는 사람이 보호자"가 됨 → **지정 보호자 번호(해시) 일치 시에만 연결** + 연결 즉시 환자 알림

### 5-3. 종이 안내지 정책 (한·일 공통)

일본은 종이 약수첩이 기본이고, 약국 조제 시스템이 종이에 표준 QR(JAHIS 전자판 약수첩 포맷)을 출력해 앱으로 가져오는 방식이 이미 쓰이고 있어 종이 안내지를 유지했습니다. 다만 **"종이는 기록과 가져오기용, 권한은 화면에서만"** 원칙으로 위험도에 따라 나눴습니다.

| 종이 | 처리 |
|---|---|
| ① 처방 등록 QR | 유지 · 1회용 · 본인 앱에서만 등록 |
| ② 보호자 연결 QR | 유지(선택) · 1회용 · 24시간 · 지정 번호 휴대폰에서만 · 분실 시 약국에서 취소 |
| 응급 QR 스티커 | **후속 검토 과제** (아래) |

### 5-4. 후속 검토 과제

- **응급 QR 스티커**: 공개할 최소 항목, 기록 기준일 표기, 약 변경 시 교체 절차, 오프라인 복호화 키 관리(의료진 단말 배포·갱신), 분실 시 무효화 동기화
- **JAHIS 전자판 약수첩 포맷 호환**: 일본 약국 QR을 그대로 가져오기 (일본 확대 시)
- **마일리지·보상**: 지자체 협의 후 확인 가능한 행동(약국 방문, 정기 점검)과 연계
- **홍보**: 초기에는 약국·보건소·지자체 소식지, TV 광고는 장기 계획

## 6. 기술 요약

- **QR 형식:** `MP1.{D|E|R|G}.{Base32}` — D 실시간(진료), E 응급(앱), R 처방 등록, G 보호자 연결
- **암호화:** AES-256-GCM (Web Crypto). QR 종류를 인증 데이터(AAD)로 묶어 종류를 바꿔치기하면 복호화 실패
- **압축:** deflate-raw 후 Base32 → QR **영숫자 모드**로 더 작은 QR. 대문자·숫자만 쓰므로 리더기가 한글 상태여도 복구 가능
- **실시간 QR:** 5분 TTL, 1회용 토큰(jti). 의료진 단말이 사용한 토큰을 기억해서 재사용 거부
- **보호자 연결 QR:** 1회용 · 24시간 · 보호자 번호는 SHA-256 해시로만 담아 보호자 앱이 자기 번호와 비교. 공유 설정에 맞는 정보만 포함
- **스캔:** USB 리더기(키보드 입력) · 카메라(BarcodeDetector → jsQR) · 이미지 파일

### 시연 버전의 한계 (발표에서 "실서비스에서는"으로 설명할 부분)
- 암호화 키가 코드에 들어 있습니다 → 실서비스는 서버 KMS/Vault 관리
- 휴대폰끼리 서버 없이 QR로만 연결합니다 → 보호자 화면은 **같은 브라우저(나란히 보기)에서만 실시간**, 다른 휴대폰에서는 연결 시점의 공유 범위만. 실서비스는 서버 동기화 + 동의 철회 시 캐시 무효화
- 1회용 처리·취소 목록·감사 로그는 그 브라우저에만 저장됩니다 → 실서비스는 Redis(TTL 토큰) + 감사 로그 DB(쓰기 전용)
- 처방전 OCR은 고정된 샘플 결과를 보여줍니다
- 감사 화면의 KPI 숫자는 가상 기준값에 실제 시연 기록을 더한 값입니다
